Executive summary

A Kali Linux machine was used to scan one deliberately vulnerable lab host, Metasploitable 2, with Nmap. The scans covered host discovery, TCP SYN scanning with service version detection, and OS fingerprinting. The results form an asset inventory of the target.

  • Target: 192.168.13.129, hostname metasploitable.localdomain.
  • Services: FTP, SSH, Telnet, SMTP, DNS, HTTP, SMB, r-services, databases, VNC, IRC and Tomcat.
  • Key observation: port 1524 reports a “Metasploitable root shell”, Telnet and the r-services are clear text, and nearly every service is very old.

This is expected for a training machine. On a real system most of these items would be rated High or Critical.

Recommendations

  • Disable Telnet and the r-services; use SSH only.
  • Remove the bind shell on port 1524 and any backdoored or unneeded service.
  • Replace FTP with SFTP and keep only one file-transfer service, if any.
  • Close or firewall NFS, VNC, RMI, X11 and the database ports.
  • Update software to supported versions.
  • Keep vulnerable lab machines on an isolated Host-Only network.

Limitations and conclusion

  • Only the top 1000 TCP ports of one host were scanned. No UDP and no full-port scan.
  • OS detection gives a kernel range, not an exact version.
  • Findings come from scan output only; nothing was exploited or independently confirmed.

Nmap found one live host with 23 open TCP ports running old and insecure services. Version detection and OS fingerprinting were enough to catalogue it as a Linux-based Metasploitable 2 machine and flag its main exposures, including a reported root shell, clear-text remote access and outdated software.
